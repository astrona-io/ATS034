# Secret Delivery And Credential Lifecycle Playground

This ungraded playground is a qemu VM (`ghcr.io/astrona-io/ubuntu-qcow2-image:24.04-cks`) with a one-node kubeadm cluster. `bootstrap/setup.sh` runs inside the VM: it initialises the cluster, gives the `student` user the admin kubeconfig, and creates the `starfleet` and `outpost` namespaces with the `shuttle` and `drifter` pods and the Secret `practice-token`.

A VM is used because the encryption at rest reading edits the real kube-apiserver static pod manifest and reads the real `etcd` data. The configuration has no submission or grading fields.

`testing/smoke.sh` takes the YAML blocks straight from the module pages and runs the page commands inside the VM (the starting state of the guide, base64 and `kubectl auth can-i`, delivery by environment variable and Secret volume, rotation and the kubelet volume refresh, immutable Secrets, and encryption at rest: the `etcd` reads, the EncryptionConfiguration file, the kube-apiserver manifest change compared with the `diff` on the page, and the rewrite of the existing Secrets). It fails when a result differs from what the page says. Run it with `scripts/ci/test-playground.sh sections/section-020/module-01/playground`; the script copies the pages into the VM over SSH and runs the smoke test there as `student`. The rotation steps of the guide are not tested, because `docs/overview.md` is not copied into the VM; the rotation page runs the same steps.
